# Baseline and root causes, 2026-11-19

The first complete live run since PRs 99-102 and `check_identity`, on the code of `main` at `c7f00a3`. It is the reference
every later experiment of this work is compared with. Reports: `docs/benchmarks/baseline-2026-11-19-all.{md,json}`
(core + reliability, 183 cases x 3), `-heldout` (6 cases x 3) and `-probe` (38 cases x 3, the frozen probe suite).
Model and configuration as in `experiment-log.md` ("The model measured on 2026-11-18": `minerva`, digest `149a0ff8a1ca`,
unchanged through the runs; thinking off; seed 7; `--compute-timeout 10`; routing on). The full run took 80.5 minutes
(4,830 s) and the held-out run 2 minutes: the "about two hours" estimate in the plan was high.

Efficiency: 258 of 798 tool calls beyond what a case needs, 33 repeated identical calls, model calls per run median 2.0
(mean 2.6), 11.2 M tokens in and 107 k out, turn latency median 7.0 s and p95 20.2 s. Targets: tool selection >= 95%
(not met), valid arguments >= 99% (not met), completion >= 95% (not met: 93.7%), false verified 0 (met), pass rate >= 85%
(not met on `all`; met on the held-out and probe suites, which are easier).

**Noise.** The three repeats of `all` differ by 5 cases (standard deviation 2.16 cases, about 1.3 points of the 170 cases):
a change smaller than about four cases per repeat is "no effect". The earlier core-only baseline (`core-live-x3-baseline`:
267/444, 60.1%) is not comparable: it predates PRs 99-102 (`check_identity`, statmech shape hints and fixes, two corrected
checks) and was core-only. The jump from 60.1% to 71.2% is those changes plus a different case set, not a result of this work.

## What failed

147 failed runs of 510. By class: tool selection 57 (23 with no tool called, 34 with a wrong first tool), arguments 24,
unproductive loop 23, model honesty 27 (21 with a tool, 6 without), resource limit 9, parsing 4, missing assumptions 3.
41 of the 170 cases fail every repeat, 19 are unstable.

By the tool the case expects (failed runs / runs): `vector_calculus` 28/51, `statistical_mechanics` 21/27,
`integrate` 12/39, `differentiate` 11/30, `electromagnetism` 10/15, `approximation` 9/18, `search_handbook` 6/12,
`matrix_calculus` 5/24, `distribution` 4/12, `integrate_motion` 3/3. Everything else is below 4 failed runs per tool.

Probe suite (86.0%): the failures are `probe-exponential-integral-needs-sign` (0/3, the model passes `k` positive to the
tool the user did not state; class invented assumption), `probe-log-power-needs-sign` (2/3, same), `probe-false-matrix-square`
(no tool), `probe-unchanged-is-an-answer` (`Simplify $x^2+y^2$` answered without the tool), `probe-laurent-expansion` and
`probe-turbulence-pde` (replies that do not say the limit in the way the case requires).

## Root causes, ranked by the failed runs each accounts for

Counts overlap where a run has two causes; each run is counted once under its failure class above.

1. **The large multiplexed tools (about 72 failed runs, 49%).** `vector_calculus` (28), `statistical_mechanics` (21),
   `electromagnetism` (10), `approximation` (9), `distribution` (4). Three sub-patterns: (a) the model gives up on the tool
   and answers in prose (10 statmech runs, 4 vector runs: the 15 k and 13 k character schemas); (b) loops of the same invalid
   or equivalent call (10 vector, 3 each statmech, em, approximation): for example `fields: [{"name": "r_minus_a"}]` for a
   translated point source, refused as an invalid field name, then sent again; (c) the wrong first tool (statmech to
   `check_identity`/`matrix_calculus`). Earlier work on statmech took 0/27 to 10/27 in three rounds; a model ceiling on the
   complex schemas is plausible and is not yet separated from the schema's cost.
2. **No tool where one is needed (29 runs, 11 cases).** Prompts whose honest answer is a refusal are answered in prose:
   `Differentiate $|z|$ w.r.t. the complex variable z` (3/3 no tool), `Taylor series of 1/x about 0 up to order 4` (3/3),
   `What is the exact value of the Planck constant?`, `Can I split log(xy) ...`, `Prove that y'=y^2+x has no closed form`,
   and the probe `Simplify x^2+y^2`. A plain imperative sentence about one formula has all its arguments in it.
3. **Reply and evidence grounding (27 honesty failures, 21 with a verified tool result).** Two kinds. Real: a correct
   restatement of a verified result is marked unchecked because of its spelling, e.g. `Compute $\int_0^\pi \sin x\,dx$` is
   answered `... = 2` with a verified tool result in 3/3 runs and fails 3/3, because `\int_0^\pi \sin x \, dx = 2` does not
   normalise like the tool's `\int\limits_{0}^{\pi}\sin{\left(x \right)}\, dx = 2` and the claim checker does not read integrals
   (the trace shows `status: unparsed`). Scoring artefacts: `unsupported-no-closed-form` fails 3/3 for a reply that says "this
   does not prove that one does not exist" (the forbidden pattern `does not exist` matches the honest sentence); several cases
   fail on `max_unchecked` for formulas the model derived itself, which Minerva rightly leaves unchecked.
4. **Arguments the tool refuses for a reason that carries no meaning (24 failed runs).**
   The largest single pattern in the traces of the failed runs: an explicit matrix given with both `entries` and
   `rows`/`cols`, refused with `give either entries or a size, not both`: 23 calls in 8 failed runs (traces are kept only for
   failed runs, so passing runs are not counted). The size is exactly the shape of the entries.
5. **Wrong first tool among valid ones (about 12 runs, partly the evaluation).** `Is cosh^2 x - sinh^2 x equal to 1?` goes to
   `check_identity` (right) and fails because the case lists `simplify`; `Solve sin x = x` goes to `isolate_variable`
   instead of `solve_polynomial`. The evaluation cannot say "also correct" for a tool that is not in `also_ok` with its own
   checks; this is what `accept:` (PR 106) is for. These cases are not edited: the core digest and baseline stay comparable.
6. **Invented assumptions (4 probe runs, 3 core runs).** The model adds `positive` to a symbol the user left complex, which
   turns a `conditions_not_satisfied` answer into a result about another problem. Nothing downstream can tell the
   difference: it is a prompt/tool-call matter, and routing removes it for the sentences it reads.

## Ranking of the candidate streams

| Stream | Addresses | Failed runs in reach | Confidence it will move passes |
| --- | --- | --- | --- |
| 2. Tool interfaces (action-specific validation, errors that name the field, repair of redundant shape) | 1 and 4 | up to ~75 | low to medium: earlier rounds moved statmech 0 -> 10 of 27 |
| 3. Routing of explicit operations | 2 and 6 | ~14 (calculus refusals, `simplify`) | medium for those sentences, none elsewhere |
| 4. Evidence grounding (spelling, one wording table) | 3 | ~10 real | high for the spelling case, nothing for scoring artefacts |
| 5. Recovery | loops in 1 | ~23 | unknown: depends on what 2 removes |

Experiments in this order, each on its own branch and measured on the affected cases against this baseline: (1) formula
spelling (cause 3, cheapest, deterministic); (2) redundant matrix size (cause 4, deterministic); (3) `explicit_operation`
routing (causes 2 and 6); then the vector and statistical-mechanics interfaces (cause 1) and recovery once their traces show
what is left. A change that does not exceed the noise (about four cases per repeat on `all`) is reverted and logged.
