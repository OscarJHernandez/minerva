# Triage of the live reliability baseline (2026-11-18)

Run `before-pr81`: the deployed `minerva` model, `--suite reliability`, 18 cases x 3 repeats, seed 7, temperature 0.2,
`--compute-timeout 10`, scoring after the `load_tools` fix. Every failed turn was exported with `--traces-dir` and read
(arguments the model wrote, tool outcome, reply). The traces are not in the repository (they hold prompts and model
output); this table is what they showed. Numbers are one run of 54 on one model: they say where to look, not how
reliable a fix will be.

| Metric | Measured | Target |
| --- | --- | --- |
| Pass | 37/54 (68.5%) | >= 90% |
| Tool selection (first mathematical tool) | 88.9% | >= 95% |
| Valid arguments | 90.0% (8 of 80 calls invalid) | >= 99% |
| Completion | 100% | >= 90% |
| False verified | 0 | 0 |
| Model calls per run | median 3.0, mean 2.9 | lower |
| Median / p95 turn | 6.1 s / 17.4 s | lower |

The previous run (`reliability-live-after-pr74`: 39/54, 77.8% selection, 92.3% valid, 17.6 s median) is not directly
comparable: it was scored with `load_tools` counted as a wrong first tool and the model host's window has changed
since. The same five cases fail 0/3 in both.

## Not justified by this evidence

- Routes for `simplify`, `differentiate`, `integrate` and `series`: in this run the model chose them correctly every
  time they were expected (simplify 12/12, differentiate 3/3, integrate 6/6 first calls). They are built only if the
  core suite run or the held-out suite shows otherwise.
- Vector calculus and distributions: no case in this suite; a coordinate system, declared fields and the delta notation
  are the user's to state.
- A Lagrangian `system` record for `@rN`: no failure retypes a Lagrangian.
